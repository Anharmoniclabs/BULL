Overview BULL Agent execution firewall
OPEN SOURCE · MODEL AGNOSTIC · LINUX ENFORCEMENT

The agent can ask.
BULL decides whether it gets to act.

BULL sits between an AI agent and sensitive host capabilities: files, shell execution, credentials, network egress, repositories, APIs, and other agents. Model output is a request. Authority stays with the host.

The basic rule is simple: untrusted information can influence what an agent wants to do. It should not automatically become permission to do it.

WHY THIS EXISTS

Do not make the thing that was just influenced by a webpage, repository, message, or another model decide whether that same input deserves shell access. BULL separates influence from authority.

REAL EXAMPLES

What BULL is trying to stop

No fake “17,000 threats blocked” counter. These are concrete authority problems the policy model handles.

01

Webpage → shell command

An agent reads an external page telling it to execute /bin/bash.

internet→process.exec→REVIEW
Externally influenced process execution is escalated instead of silently launched.
02

Webpage → credential

External content convinces an agent to request a token or credential.

internet→credential.read→DENY
External credential access is a hard block in the deterministic policy.
03

Child agent escalation

A parent only has project-read authority. Its child asks for credential access.

parent ceiling→child request→DENY
Authority cannot appear just because another agent was spawned.
04

Goal drift

An agent spends several actions reading a project, then abruptly pivots toward credentials.

project work→privilege shift→GOAL_DRIFT
The session guard raises scrutiny across the action sequence, not only one request at a time.

MULTI-AGENT AUTHORITY

Spawning another agent does not create new permission

BULL can issue host-owned security domains with lineage, capability ceilings and egress ceilings.

ROOT AGENTread · write · execute · spawnShared root behavioral history
CHILD Areadsubset of parent authority
CHILD Bread · executesubset of parent authority
CHILD REQUESTcredential.readDENY — parent never granted it

Identity comes from the host. Model-provided domain IDs, provenance or authority metadata are not accepted as trusted context.

Siblings do not reset history. Agents keep distinct identities while sharing their root domain's behavioral security context.

Serious violations can freeze the tree. A hard block or cross-agent behavioral violation can freeze the entire root domain.

SCOPED BROKERS

Secrets and network access stay outside the raw workload

Instead of handing a sandbox every credential and a normal network stack, BULL mediates privileged access through host-side brokers.

SECRET BROKER

Give the action the secret it earned — not the whole environment

policy authorization→scoped token→Unix broker→specific secret
  • allowed secret names
  • TTL expiration
  • sandbox/domain binding
  • maximum-use limits
  • revocation and peer authentication
EGRESS BROKER

Outbound access is a capability, not a default network socket

host allowlist→DNS validation→IP pin→TLS hostname check
  • private / loopback / metadata-style destinations fail closed
  • mixed public/private DNS answers fail closed
  • HTTP method restrictions
  • response-size limits
  • redirects require reauthorization

What a green build does not prove

Passing CI does not mean BULL is vulnerability-free.

TLA+ checks the modeled state machine, not the full Python/Linux implementation.

Host certification proves requested controls were observed on that host; it is not a proof against kernel or hypervisor compromise.

BULL has not undergone an independent third-party security audit.

SECURITY BOUNDARY

What BULL does not claim to solve

Security software gets more credible when it states the boundary plainly.

Compromised kernel / hypervisorBULL trusts the Linux kernel and outer host boundary.
Malicious host administratorThe host and BULL trusted computing base remain trusted components.
Hardware attacksThis is not a hardware-rooted confidential-computing system.
All side channelsSeparate mutually hostile tenants into separate VMs or microVMs.
Bad actions inside granted authorityIf you explicitly grant an ability, policy cannot magically make every use harmless.
Unknown implementation bugsTests and formal models cover the cases they actually encode, not every future bug.

Current platform reality

Linux strict enforcement is implemented. macOS and Windows have backend contracts but deliberately fail closed until native enforcement exists. BULL does not silently fall back to an unrestricted subprocess and call that “portable security.”

What BULL still needs to become plug-and-play

First-class adapters for real agent runtimes: MCP, coding-agent tool execution, IDE agents, and a clean daemon/gateway surface. The core security pieces exist; distribution and integration are the next product layer.
